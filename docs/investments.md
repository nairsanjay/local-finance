# Investment statements

Open **Import Statements**, then choose **Investments** alongside **Bank & credit cards**. Attach or drag in one or multiple files, inspect each detected portfolio preview, and import ready statements individually or together. The upload page discovers supported providers and extensions from the parser registry: Zerodha holdings `.xlsx` and INDmoney US stock holdings `.xls` (up to 10 MB per file). Previews never save data. **Investments** in the sidebar shows invested amount, available statement valuations and unrealized returns, and individual holdings. Search by symbol or ISIN, filter asset classes, and open **Statement details** to inspect every worksheet field.

These are dated holdings snapshots, not live market valuations. Returns do not include realized trades, dividends, charges, or cash flows absent from the workbook; annualized return and XIRR cannot be inferred. Different snapshots are selectable and are never added together. Re-uploading the identical file, even with a different filename, returns the existing snapshot. Delete a snapshot to remove an accidental import.

The top of Investments and the main dashboard show total holdings separately for each statement currency. Each provider/account/currency contributes only its latest statement date (then latest import for same-day revisions); selecting a historical snapshot does not change these totals. Current value remains unavailable if any account in that currency lacks a market valuation, with any known subtotal labeled separately. Date ranges are shown when account statements differ. No exchange rates are fetched or applied.

Investment records use a separate SQLite table. They never create bank accounts or ledger transactions and do not change income, expense, cash-flow, or budget calculations. Database backups, JSON export, and database reset include investments.

## Adding providers

Implement `investment.Parser` (`ID`, `Info`, `CanParse`, `Parse`) and register it from its own `init()` in `investment.DefaultRegistry`. `Info` supplies the provider, statement name, and supported file extensions through `/api/investments/formats`. The Investments UI discovers supported providers, file picker extensions, and the upload limit from this endpoint; adding an adapter requires no provider-specific page changes. Adapters normalize provider-specific files into `models.InvestmentSnapshot` and `models.InvestmentHolding`; the service, persistence, HTTP endpoints, and UI use only these shared types. Keep additional provider fields in `Fields` and worksheet data in `Sheets`. Detection must use workbook structure rather than a user's filename or account number; ambiguous matches are rejected.

The first adapter reads Zerodha's Combined sheet when present to avoid counting repeated Equity and Mutual Funds sheets twice. It retains those original sheets for inspection. Without Combined, summary and disclaimer worksheets are retained without being treated as holdings tables; malformed holdings tables are still rejected. Quantities include available and pledged holdings, without adding the long-term subset. Current value is quantity times previous closing price. Cost basis is current value minus the statement's reported unrealized P&L, which preserves precision lost in rounded average prices. Combined summary totals must reconcile within ₹1.

The INDmoney adapter reads legacy Excel US holdings reports identified by their account/date metadata, holdings columns, and provider attribution. It preserves fractional quantities, holding dates, broker details, and all worksheets. **Total Value ($)** is the current holding valuation, and **Avg. Price ($)** is its statement valuation price; these must reconcile with quantity within one cent. These exports do not provide acquisition costs, so invested amount, average cost price, unrealized return, and return percentage remain unavailable (`null` in the shared API). Amounts remain in their statement currency; USD and INR snapshots are never converted.

Use fictional, generated workbooks for tests. Never commit personal holdings, account identifiers, statement files, validation databases, or screenshots containing personal data.

Zerodha documents dated holdings exports in its [holdings report guide](https://support.zerodha.com/category/console/portfolio/console-holdings/articles/holding-report), and distinguishes pledged from remaining available quantities in its [pledged holdings guide](https://support.zerodha.com/category/trading-and-markets/general-kite/kite-holdings/articles/p-symbol-kite-holdings).

Migration 00015 creates the investment snapshots table and its portfolio/date index. It is the only investment migration, following main’s version 00014. Startup applies it automatically on fresh installations and existing main databases.
